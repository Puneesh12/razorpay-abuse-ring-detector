The mechanism

Four steps, none of them a black box.

Every stage is inspectable — the graph is deterministic, the score is a real held-out-evaluated model, and the decision is a fixed policy, not a vibe.

01

Build the graph

Accounts sharing a device fingerprint, payout account, or address become connected nodes — a deterministic fact, not a prediction.

02

Score the cluster

A classifier trained on registration bursts, refund rate, and attribute reuse scores whether the cluster's behaviour looks coordinated.

03

Write the case file

A reasoning layer turns the evidence into the argument a human analyst would write — free, deterministic, no API key required.

04

Queue for review

A fixed policy decides no_action, queue_for_review, or priority_review. Nothing here can ban, freeze, or suspend.

Why this isn't a clone

Razorpay already ships fraud agents. Not this one.

Agent Studio's Dispute Responder and Recovery agents work per-transaction, per-merchant. This is the layer underneath them.

Vantage point

Only Razorpay can see this

The same device or payout account touching three unrelated merchants is invisible to any single merchant's fraud team — visible only to the platform sitting underneath all of them.

Safety

Strictly defense-only

No ban, freeze, or suspend anywhere in the codebase. Every action is a review-queue decision. A human always makes the final call.

Honesty

Real held-out numbers

Precision, recall, and false-positive cost measured against a naive baseline on data the model never trained on — not a cherry-picked demo. (Small test-n, stated plainly in docs/EVALUATION.md, not hidden.)
